# 最简化 RAG 系统需求文档

## 1. 目标
在当前项目中实现一个最简化的 RAG（Retrieval-Augmented Generation）系统，提供 HTTP 接口接收查询字符串，经过向量检索与 LLM 总结后返回回答。

## 2. 范围
- 使用 FastAPI 提供简单 HTTP 服务。
- 使用 FAISS 作为本地文件化向量数据库。
- AI 模型通过 OpenAI 兼容 API 调用（Embedding + Chat Completion）。
- 提供从 MongoDB 导入数据并全量重建向量索引的脚本。

## 3. 功能需求
### 3.1 查询服务
- 提供 HTTP 接口（如 `POST /query`），输入为查询字符串。
- 服务端流程：
  1. 将查询字符串转为向量；
  2. 在 FAISS 中检索 Top-K 相关文档；
  3. 将检索片段拼接为上下文，调用 LLM 生成总结回答；
  4. 返回回答及基础检索信息（如命中片段与分数）。

### 3.2 数据导入与建索引
- 提供脚本从 MongoDB 读取数据。
- 按配置指定字段拼接可检索文本。
- 调用 Embedding 模型生成向量。
- 全量重建 FAISS 索引及配套元数据文件。

### 3.3 配置管理
- 统一从 `config.json` 读取运行参数。
- 至少包括：
  - MongoDB 连接信息（URI、数据库名、集合名）；
  - 文本字段映射配置（可检索文本由哪些字段拼接）；
- 模型提供方配置，需支持 Chat 与 Embedding 分开配置（如 chat 走 OpenAI，embedding 走 Ollama）；
  - 向量检索参数（top_k 等）；
  - 本地索引与元数据文件路径。

## 4. 非功能需求
- 尽可能少依赖第三方库。
- 代码与注释使用英文。
- Python 代码需包含 Type Annotations。
- 对外公共函数需有简洁 Docstring（一行）。
- 目录结构需按组件解耦，至少分离：
  - Web Service 层；
  - LLM / Embedding 模型接入层；
  - 向量数据库访问层；
  - 主入口编排层（负责装配与启动整体流程）。

## 5. 约束与说明
- 当前阶段 MongoDB 具体 schema 未确定，代码需通过配置参数预留字段位并附带注释说明。
- 当前导入脚本只需支持全量重建，不要求增量更新。
- 使用单机本地文件化存储，不引入独立向量数据库服务。
